# Workflows redesign (2026-09-21): Council, Discover, Build + Review

Sal's brief: significantly improve the design and functionality of the three workflows reached
from **＋ → Workflow**: **Build + Review**, **Council**, **Discover**. Council must work the
way Karpathy's llm-council does, Discover must work the way the ultracode workflow it came from
does, Build + Review gets a **wrench** icon, and every workflow shows **live updates** while it
runs.

This document is the contract the implementation follows. Paths are relative to the repo root.

## 1. What was wrong (measured on main-next `8096a89914`)

- Council and Discover could not start on a Mac with current CLIs: the catalog demanded the exact
  string `grok 1.0.30 (04b7ffed98c6) [stable]`; installed Grok is 1.0.34.
- Every workflow agent ran in an empty temporary folder with all tools disabled and saw only a
  hand-ticked "frozen evidence" blob (≤128 KB, ≤64 files, first 256 files alphabetically, so on
  this repository not a single `src/` file could be picked). Prompts told models to use "only
  the frozen evidence", which suppressed general knowledge.
- Council: exactly 3 seats of 3 distinct families, Gemini banned even from answering, answers
  forced into JSON, each reviewer saw only the two other answers (so every ballot was one
  pairwise comparison and scores could only be 0, 0.5, 1), one failed seat failed the run, raw
  `<pre>` markdown in the default view, jargon everywhere.
- Discover: one finder model for all "dimensions" with a one-sentence prompt, ≤4 findings per
  dimension, ≤12 total, exactly 2 skeptics bound to fixed lenses, uncertainty forced to count as
  "refuted", no loop, no repo access, 120 s timeouts, any single failure failed the run.
- Nothing was live: stage/log events were dropped (`progress: () => {}`), output only existed
  after a process exited, the renderer polled every 2 s only while the tab was visible, and the
  sidebar row said "queued" forever. Build + Review had no icon.

## 2. Principles

1. **Real work, not a demo.** Agents read the actual workspace (read-only) unless the user turns
   that off. Timeouts are minutes, not seconds.
2. **Faithful to the sources.** Council follows `karpathy/llm-council` (stage prompts, anonymous
   ranking of *all* responses, `FINAL RANKING:` parsing, average-rank "street cred", chairman).
   Discover follows the canonical ultracode shapes: `review-changes` pipeline, exhaustive-review
   loop-until-dry with a 3-lens panel, the `er2-crossfamily-bughunt` cross-family verify and
   blast-radius rank, and the deep-research 3-vote tally (2 refutes kill, missing evidence is
   *unjudged*, never a kill). The original Discover `.js` was not found on disk; this is a
   reconstruction from those sources.
3. **Degrade, don't die.** A failed member, finder or verifier is shown as failed and the run
   continues with what succeeded. Only a failed final step (chairman/ranker) fails the run, and
   Retry re-runs just that step (accepted calls replay from the journal).
4. **Estate rules hold.** Gemini may do work but never issues a verdict (`model-lineage.ts`
   `mayIssueVerdict`): in Council it answers but does not rank and cannot chair; in Discover it
   may find but never verifies or ranks. A reviewer's vote on its own (anonymous) response is
   excluded from the aggregate ("the seat that reviews work is never the model that produced
   it").
5. **Everything live.** Per agent: waiting / starting / running / finishing / done / failed,
   elapsed time, what it is doing, a live tail of what it is writing, tokens. Pushed, not polled.
6. **One design.** Same preset icon, name and state everywhere (menu, setup, run header, tab,
   sidebar row). Monochrome, colour only for state, tokens from `main.css`, lucide icons,
   `CommentMarkdown variant="document"` for answers, no internal jargon on the main path.
7. **Durable and replayable.** New behaviour ships as **Council revision 6** and **Discover
   revision 7**. Council revisions 1–5 and Discover revisions 1–6 stay byte-identical for replay
   (their tests pin them). Council 5 and Discover 6 are the working-agent programs from PR #539
   (section 9); runs at those revisions exist on installed apps.

## 4. Council (revision 6)

### Setup (prompt first)
- A composer at the top: "Ask the council…" (Enter sends when valid, Shift+Enter newline).
- **Members**: chips, one per seat, each showing `AgentIcon` + model name (e.g. "Claude Opus 5",
  "GPT-5.6 Sol", "Grok 4.6", "Gemini 3.8 Flash"). Add/remove (2–6 members). Clicking a chip
  opens account/model/effort. Default: every available route once (Claude, Codex, Grok, Gemini),
  i.e. Karpathy's default council (GPT, Claude, Grok, Gemini).
- **Chairman**: a select of every eligible (non-Google) seat, default Claude. The chairman may
  be a member or not.
- **Agent access** select (section 9; default **Read this workspace**) + optional **Attach
  files** (existing scope list, collapsed, searchable). *Knowledge only* = pure knowledge
  answers (exactly Karpathy).
- **Advanced** (collapsed): concurrency. No call budgets or attempt arithmetic on screen; the
  host derives them (calls = members + voters + 1).
- One line of honest copy: "Gemini answers but never ranks or chairs (your review rule)." shown
  only when Gemini is a member.

### Program (`presets/council-v6.ts`, dispatched by `workflow-preset-runner.ts` when `revision === 6`)
Seats: `members` (2–6 distinct seat ids), `chair` (one seat id), `voters = members.filter(lineage
!== 'google')` (≥1). Labels `Response A…` follow member order and never change.

1. **Stage 1 – First opinions** (`phase('First opinions')`), `parallel` over members, call id
   `answer/<seatId>`, output **text** (final message becomes `{ markdown }`). Prompt = the user's
   question verbatim, preceded only by this context when `access === 'workspace-read'`:
   `You are one member of a council answering the question below. You are running inside the
   user's workspace at the current directory and may read files (read-only) to ground your
   answer. Cite files as path:line when you rely on them.` and, when files were attached, the
   attached files as plain text blocks `--- path ---` with line numbers. Nulls are dropped; zero
   answers fails the run.
2. **Stage 2 – Peer rankings** (`phase('Peer rankings')`), `parallel` over voters, call id
   `rank/<seatId>`, output **text**. Prompt = Karpathy's Stage 2 prompt verbatim, with **all**
   successful responses (including the voter's own) anonymised as `Response X`. Presentation
   order rotates per voter (position-bias control) but labels never change. `validateSemantics`
   rejects only a ballot from which no label can be parsed. Parsing = Karpathy's
   `parse_ranking_from_text` (split on `FINAL RANKING:`, numbered `Response X`, then fallbacks),
   deduplicated, restricted to known labels.
3. **Street cred** (code, no call): for each label, positions (1-based) from every parsed ballot
   *except the ballot of the member who wrote that response*; `averageRank` rounded to 2
   decimals, `votes`, `place` (ties share a place). Sorted ascending.
4. **Stage 3 – Chairman** (`phase('Chairman')`), call id `chair/final`, output **text**.
   Prompt = Karpathy's chairman prompt verbatim with de-anonymised Stage 1
   (`Model: <modelLabel>\nResponse: …`) and Stage 2 (`Model: <reviewer>\nRanking: <full text>`,
   where each mention of an answering member's label — `Response X`, `Response X's`, or a list
   such as `Responses A and C`, `Response A/B`, `Response B vs. A` — is replaced by that member's
   numbered model name; the label of a member that never answered stays as written, and a list
   that starts with one is kept whole, as are a range such as `Responses A-C` and a bare letter),
   plus the street-cred table, plus one line telling the chairman to refer to members by model
   name, never by response letter, plus, for workspace-read, "You may read files to check
   disputed claims." Failure fails the run (Retry reruns only this call).

Timeouts: answer 15 min, rank 10 min, chair 15 min (per call `timeoutMs`).

### Run view (Karpathy layout, polished)
- User bubble with the question. Tab title becomes the first ~48 chars of the question.
- A vertical **stage rail** (style of `next-action/up-next-rail.tsx`): 1 First opinions ·
  2 Peer rankings · 3 Chairman's answer, each with its live state and `done/total`, and while a
  stage runs a label like Karpathy's ("Collecting individual responses…").
- **Stage 1** card: `Tabs` (variant line), one tab per member: `AgentIcon` + model label + state
  dot (pulses while running). Body: live tail while running (streaming text), then the answer
  as `CommentMarkdown variant="document"`; footer: elapsed · tokens · "Details" (logs).
- **Stage 2** card: explainer "Each model ranked every answer without knowing who wrote it.
  Model names are shown here for readability." (revisions 1–5: "Each reviewer ranked the other
  answers anonymously.") Tabs per voter; the evaluation with `Response X`
  replaced by **model label**; "Extracted ranking" ordered list; then **Street cred**: place,
  icon, model, average rank (2 dp; an answer with no counted vote shows "—" and sorts last),
  votes, with the note "A model's vote for its own answer is not counted." (revision 6 only).
- **Stage 3**: highlighted card (success tint border only when completed), "Chairman · <model>",
  the answer as document markdown, actions: Copy, Save as file, Ask a follow-up, New question.
- Failed calls show inline ("Grok didn't answer — timed out after 15:00") and never blank the
  page.

## 5. Discover (revision 7)

### Setup
- **Goal** composer: "What should Discover look for?" (placeholder "Find real bugs in the
  checkout flow"). Required.
- **Focus** (optional): folders/files to focus on, from a searchable picker (directories
  allowed) or typed paths. Default: the whole workspace. Without workspace access a focused
  folder attaches only its readable listed files (a folder entry is never attached or counted);
  working agents also keep a listed folder itself as a starting reference, so a folder whose
  files the host did not list still counts. Only a path the host never listed is refused there.
- **Lenses** chips (multi): Correctness (default on), Reliability (on), Security (on),
  Performance, User path, Data integrity.
- **Depth**: Quick (1 round) · Thorough (default, up to 3 rounds, stop after 1 dry round) ·
  Exhaustive (up to 5 rounds, stop after 2 dry rounds). Show the agent range from the planner
  itself (`estimateDiscoverAgents(lensCount, depth, maxAgents)` in
  `shared/local-workflow-draft.ts`: `low` = the true floor, no map (one area) and nothing found;
  `high` = the true ceiling over every map and every count of new findings per round, each
  round's repeat check and Rank included, never above the maximum; present it as "up to").
- **Team**: finder chips (default Claude, Codex, Grok; Gemini allowed as finder), ranker select
  (non-Google, default Claude). Verifiers are automatic: every non-Google seat, rotated so a
  finding is never verified by the family that found it when another family exists. Admission
  freezes `host.serializedSeats`: the Codex seats whose login the launcher's own check
  (`local-workflow-codex-launch.ts`, for a vote started then) finds due to refresh, so their calls
  would take the account one at a time. Votes avoid those seats whenever another eligible
  non-finder family can take them, and a serialized finder keeps only its first job of a round
  (job order) while another finder exists, the rest going round the other finders, so its jobs
  never queue into the tail of Find; the rotation reads only the frozen snapshot, so replay routes
  the same way. Admission also freezes `host.discoverRules` (`DISCOVER_V7_RULES`, now 2). A
  snapshot without it was admitted before the serialized-finder rule and before jobs could report
  past their share (step 2), so the program and the view plan it with the plain rotation and each
  job's share only, as it ran.
- Advanced: concurrency, maximum agents (default 160, minimum 6, hard ceiling 400; below 6
  the scout, one finder job with room for three votes and the Rank reserve do not fit, so no
  finder job would run).

### Program (`presets/discover-v7.ts`)
1. **Scout** (`scout/map`, ranker seat or first finder, schema `discovery-areas-v7`): read the
   focus/workspace and return 2–8 areas `{ name, files[], why }` relevant to the goal.
2. **Find** — `jobs = areas × lenses`, all finders of a round in parallel, finder family
   `finders[(areaIndex + lensIndex + round) % finders.length]`, call id
   `find/r<round>/<areaIndex>/<lensId>`, schema `findings-v7` (≤8 findings per job, each
   `{ title, file, line, endLine?, severity, trigger, scenario, evidence, fix? }`, plus
   `filesRead`, the workspace-relative files the finder opened). Budget (`discoverRoundBudget`): a
   round starts only the jobs whose every possible finding can still get its 3 votes, and keeps one
   call for its repeat check when it may report two findings and the check costs no finder job;
   each job keeps votes for its share and may report up to the round's whole verifiable number
   (at most 8, "Report at most N defects"). Once every batch is in, the votes jobs did not need go
   to findings past other jobs' shares, breadth first in job order; what still finds no votes, or
   lies past N, is set aside and logged, and unused reservations return to the budget. A batch is admitted (code dedup, ids) as
   soon as every earlier job's batch is in; nothing is verified before the round's last batch is
   in and its repeat check (step 3) has answered. The next round starts after that check, without
   waiting for the round's votes. `validateSemantics` rejects placeholder answers (placeholder
   words, too-short fields, a file that is not a workspace-relative path, line < 1) and, for a
   workspace-read finder, an answer whose `filesRead` is empty or names no path inside its area
   (an area entry may be a file, a folder or a glob, read by its literal lead)
   ("Open the area's files before answering; you reported none."), so the call retries with the
   problem named; frozen finders are exempt. Prompt (er2):
   goal, area files, lens instruction, "Read those files completely. Trace the actual control
   flow. Report only defects you can point at in code with file:line and a concrete failure
   scenario. Be adversarial: assume every guard has a hole and go find it. Already known (skip):
   …".
3. **Dedup**, first in code against every earlier verified report (never against a repeat, so
   matches do not chain): same file, line ranges overlapping or within ±12 lines, and title words
   (camelCase/snake_case split, stopwords dropped before plurals) with Jaccard ≥ 0.5. That key only
   catches close wording, so once every finder of the round is in, if two or more of the round's
   fresh findings are in the same file, **one repeat check** (`find/r<round>/repeats`, ranker seat,
   schema `discovery-repeats-v7`, `{ groups: [{ findingIds, rootCause }] }`) groups all of the
   round's fresh findings by root cause: same root = the same violated condition, so one fix
   removes both, not merely the same lines; distinct defects stay apart. Code checks the answer is
   a partition of exactly those ids (otherwise it retries with the problem named); in each group
   the earliest report in job order is verified and the rest are recorded as its repeats
   (`duplicateOf`), giving back their votes. A check that never answers merges nothing. It is
   journaled like any call, so replay applies the same merge; a round whose budget had no call
   left for the check says so in Notes and verifies every finding.
4. **Verify** each fresh finding with **3 votes** in parallel, lenses `correctness`
   (is the mechanism real?), `reachability` (can the trigger happen in a supported path; look
   for upstream guards), `reproduction` (construct concrete input/state → wrong result). Call id
   `verify/<findingId>/<lens>`, schema `verdict-files-v7` `{ verdict: 'real'|'refuted'|'unjudged',
   reason, evidence, filesRead }`; `validateSemantics` rejects a vote with no evidence or, for a
   workspace-read verifier, no file read (a placeholder such as "n/a" or "." is none; "Open the
   files before voting; you cited none."), so the call retries with the problem named. Prompt:
   "Your job is to REFUTE it if you can. Open the files. Trace the real control flow… If you
   cannot establish either way from the code, answer unjudged." Tally:
   `real ≥ 2` → confirmed; `refuted ≥ 2` → refuted; otherwise unverified. Null votes are
   *unjudged* (infrastructure), never refutes.
5. **Loop until dry** per depth: next round re-runs Find with every known finding; a round with
   no fresh findings counts as dry. Every cap that drops work is `log()`ged and shown ("No
   silent caps").
6. **Rank** (`rank/final`, ranker seat, schema `discovery-report-v7`): merge same-root
   duplicates keeping provenance, rank by blast radius, and give each item `{ rank, title,
   location, severity, scenario, fix, findingIds[], parallelSafe }` plus a markdown `summary`
   (told the exact counts and not to restate them; code writes the count line above it);
   refuted and unverified are listed separately by id. A repeat reaches Rank only as provenance
   of its original, with no verdict of its own, so Rank never receives two verdicts for one
   reported defect; every verified report keeps its own verdict. The refuted and unverified lists
   come from the verdicts: the ranker returns them empty and whatever it puts there is replaced,
   never rejected.

Timeouts: scout 10 min, find 20 min, verify 10 min, rank 10 min.

### Run view
- Goal bubble, rail: Scout · Find · Verify · Rank with live counts ("round 2 of 3").
- Areas as chips once Scout lands.
- **Findings feed**, live: a card appears the moment a finder returns it: severity chip, title,
  `file:line` (opens the file), found-by icon, three verdict dots filling in as votes land
  (✓ real, ✗ refuted, ? unjudged), status Waiting to verify (no vote started yet) / Verifying /
  Confirmed / Refuted / Unverified; the Verify stage header counts the two apart ("1 verifying ·
  2 waiting to verify · …"). Filter chips: Confirmed · Unverified · Refuted · All. Notes
  count what was verified ("Verified 16 of 30 reported findings (14 repeats set aside): …"),
  never a number of distinct defects.
- **Report** (after Rank): ranked cards with scenario, fix, "can run in parallel" badge and a
  **Fix with Build + Review** button that opens a Build + Review conversation prefilled with
  the fix as its objective.

## 7. Live updates (all presets)

- **Main:** `LocalWorkflowLiveRegistry` (in memory, per execution) fed by: the execution
  service's agent wrapper (waiting for a slot), the provider launcher (lock wait, spawn, stdout
  chunks parsed per provider into activity/tail/tokens, exit), the program's `phase()`/`log()`
  (now wired, no longer `() => {}`), and store changes. `recordLaunch` bumps `sequence`.
- **Push:** streaming RPC `localWorkflow.watch` (`defineStreamingMethod`, same pattern as
  `agentSession.subscribeStatus`) emits the full view (without stdout/stderr) on subscribe and
  whenever the durable sequence or the live registry changes, throttled to ≤ 4/s.
  `localWorkflow.readCall` returns one call's logs on demand. A window notification
  `localWorkflow:changed` carries `{ conversationId, executionId, preset, state, running,
  completed, total, phase }` so the sidebar and tab strip update while the tab is hidden.
- **Renderer:** the projection hook subscribes (10 s poll only as a fallback), a store slice
  keeps per-tab workflow status, the sidebar row shows the preset icon + real state (working /
  done / failed / needs you), the tab shows the preset icon with a state dot.
- Build + Review keeps its existing `buildReview:changed` push; the redundant 2 s interval is
  removed; worker cards read live hook rows.

## 8. Executor changes (main)

- CLI versions: minimum versions, not exact strings; attestation checks the parsed version.
- `snapshot.access = 'workspace-read'` + frozen `host.workspaceRoot { path, device, inode }`.
  Read-only tools per provider (see the provider section, measured by probes on 2026-09-21).
  Private per-attempt files (schema, instructions, Codex home, Grok profile) stay under
  `inputs/<attemptId>`; nothing is written into the user's repository.
- `WorkflowProgramCall` gains `output?: 'text'` (final assistant text is wrapped as
  `{ markdown }` before validation) and `timeoutMs?` (not part of call identity).
- Parsers accept both the old single-envelope output and the streamed output (take the last
  result line / the last agent message).
- Retries append the previous attempt's problem to the prompt; the host allows 2 attempts per
  run.
- Models: each route exposes its verified model list (alias → resolved id), not one pin.
- Gemini route: answer/find only (`gemini-3.8-flash`).
- Token usage from receipts is summed into `view.usage.tokens` and per call.
- DB: `local_workflow_executions.call_limit` ceiling raised (schema **v41** table copy, applied
  after PR #539's v40 working-agent tables) so Discover can run up to 400 calls. A pre-release
  build that stored the 400-call table as v40 without the working-agent tables is replayed from
  v39 (`orchestration-schema-version-skew.ts`).
- Revision constants live in `workflow-program-revisions.ts` (`COUNCIL_REVISION = 6`,
  `DISCOVER_REVISION = 7`, `WORKING_COUNCIL_REVISION = 5`, `WORKING_DISCOVER_REVISION = 6`).
- Grok: the frozen legacy argv is unchanged; `grok-1.0.40-frozen-v1` (PR #539's pin) stays an
  accepted prior policy revision so its runs replay and take follow-ups.

## 9. Working agents (PR #539) and Agent access

- `draft.capability` is `'frozen-analysis'` (default) or `'working-agent'`; the snapshot pins
  `capability: { mode, revision: 1 }`.
- **Routing.** `capability === 'working-agent'` takes PR #539's admission
  (`local-workflow-working-admission.ts`) and `WorkingWorkflowExecutionService` unchanged: three
  seats from three families (Claude, Codex, Grok), the chairman or ranker among them, one durable
  Dispatch per call in an isolated child worktree, Council revision 5 (pinned blind labels,
  candidate packets) and Discover revision 6 (reviewed ranking), call limits 7 / 30. Every other
  draft takes this redesign's path (`local-workflow-host-admission.ts`): `snapshot.access =
  'workspace-read'` unless `draft.access === 'frozen'`, Council revision 6, Discover revision 7.
- **Setup.** One **Agent access** select in the composer footer: *Read this workspace* (default;
  read-only tools, live), *Working agents · edit isolated copies* (switches the lineup to one
  Claude, one Codex and one Grok, hides lenses, depth, max agents and outside chairmen, and names
  the rule when the lineup breaks it) and *Knowledge only · no files* (`access: 'frozen'`;
  Discover names it *Attached files only*, since it then reads only the focused files). A draft
  with no `access` field shows *Read this workspace*, the access the host grants it.
- **Run view.** Working runs project into the same `councilRun` / `discoverRun` shapes (best
  effort, never throwing); worker output comes through `orchestration.workerRead` for Details,
  and a call whose worker terminal is still open (release not requested, or retained) carries
  its `terminalHandle`, so **Open terminal** brings that real terminal forward.
